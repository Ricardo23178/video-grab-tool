# Windows 链接归档工具设计规格

日期：2026-10-20

## 目标与已确认需求

用户把抖音或 B 站的作品链接交给 Windows shell 命令，工具保存作品原有的视频、图片和文字，以及标题文案、发布时间和作品公开标注的地点。日常按链接批量处理，不需要手机分享入口。

用户已选择第一版只保存原始内容和平台信息，不分析视频声音和画面，不生成 AI 内容摘要，也不提取音画中的事件时间、地点。因此本版不需要模型服务、API Key 或模型下载。

## 方案选择

推荐：用一个薄 Python 命令行入口调用成熟的平台工具，统一归档路径、字段和批处理结果。抖音以 F2 为候选，B 站以 BBDownNext 为候选。先验证真实链接下载和原始元数据是否满足需求，再锁定工具版本，不能把 README 功能声明当作实测通过。

另一种可行方式是分别直接使用两个工具，用户自行整理文件；安装工作略少，但不能直接提供统一的信息文件、去重和失败清单。用户当前场景采用统一入口。

不重写平台签名、鉴权算法或音视频下载器；上游工具失效时明确失败原因并保留已成功下载的结果。不存在永久适配平台的承诺。

参考项目：

- F2：https://github.com/Johnserf-Seed/f2 ，Apache-2.0。公开代码能处理作品时间和文案；具体作品定位需检查原始响应，不能预先保证都有。
- BBDownNext：https://github.com/KaiHuaDou/BBDownNext 。项目声明支持视频和图文导出；实现前检查所用版本的许可证和运行依赖。
- B 站原版 BBDown 已归档：https://github.com/nilaoda/BBDown 。不以旧版维护状态推断新版本可用性。

## 命令界面

从工具目录运行 PowerShell，以下是计划实现的命令，不是已经存在的命令：

```powershell
# 保存一条作品，默认输出到 D:\Codex\视频资料
.\grab.ps1 "https://v.douyin.com/作品短链接/"

# 指定输出文件夹
.\grab.ps1 "https://www.bilibili.com/video/BV作品编号/" -OutDir "D:\视频资料"

# 每行一个链接，逐条处理
.\grab.ps1 -InputFile ".\links.txt" -OutDir "D:\视频资料"
```

支持抖音和 B 站的具体作品长链接与官方短链接。接受 URL 中的查询参数。批处理清单使用 UTF-8，可带 BOM，忽略空行。链接参数与 InputFile 二选一，错误输入在请求网络前报告。

第一版按给定作品链接处理；不自动扫描推荐流、关注列表、账号空间或收藏夹。

## 内容与信息保存规则

每个作品对应一个目录，以平台和作品 ID 识别，同一作品的短链接与长链接不能重复下载。

```text
D:\Codex\视频资料\
    抖音\作品ID\
        视频.mp4             # 视频作品保存；实际封装沿用下载结果
        图片\001.jpg         # 图集按原顺序保存，保留真实图片格式
        信息.md
        信息.json
    B站\作品ID\
        ...
```

信息.md 供人阅读；信息.json 记录同样的规范化字段及完成状态，用于后续核对和去重。纯文字只需要信息文件；图文正文保留段落和图片顺序。B 站多 P 视频按分 P 分别保存，避免仅保存第一 P 却将整条作品标记为完成。

必备字段：

- 平台、作品 ID、原始输入链接、规范化作品链接。
- 标题、作者显示名称、原始作品文案或正文。平台没有独立标题时明确说明，不用 AI 另编标题。
- 发布时间：保留原始时间戳或平台原始文本，同时以 Asia/Shanghai 转为可读时间；未知精度不补造。
- 作品公开标注的地点：平台提供的作品级定位，原样保留名称与平台明确提供的行政区域；不逆向推断精确位置。
- 保存时间、原件文件清单、归档完成状态。
- 字段缺失说明与下载失败原因，不记录密码、Cookie、访问令牌或临时媒体签名 URL。

地点必须区分“有公开定位”“作品未提供”“本次未能获取”。不能把接口失败写成作者没有标注定位；不能把用户主页地区、作者 IP 属地、标题出现的地名或画面推断当成作品发布地点。本版不另行查询作者资料来补齐地点。

没有公开定位不阻止保存原件。定位也不代表实际拍摄地点。

## 执行与失败处理

流程：校验输入 → 识别平台及作品 ID → 检查已完成归档 → 调用对应工具获取内容及元数据 → 核对实际产物 → 写入信息文件与完成状态。

- 默认串行处理；不引入服务、任务数据库或消息机器人。
- 临时文件写在对应任务目录，完整下载并核对后才计为成功；不能只凭进程退出码或文件存在就认定成功。
- 完整归档再次输入时跳过，不覆盖原件；不完整任务允许重试。已存在的非本工具文件不覆盖。
- 网络临时错误最多重试 3 次并逐渐延长等待；未登录、登录失效、无权限、验证码或风控拦截时停止该项的自动重试并说明原因。
- 批次内单项失败继续处理其他作品；结束显示成功、跳过、失败的数量和失败链接。失败记录不得携带凭据。
- 退出码：0 表示全部完成或已完成而跳过；1 表示存在处理失败；2 表示参数、依赖或配置错误。
- 遇到未支持的作品类型，明确提示，不把空目录标记为下载成功。

## 登录与目录约束

使用用户本机的授权账号，通过所选上游工具支持的登录方法配置。无需用户在聊天里提供密码或 Cookie。不自动修改已有浏览器配置，不改变系统安全策略，不绕过无权访问的内容。

项目目录：D:\Codex\视频解析项目。

默认归档目录：D:\Codex\视频资料；每次可用 OutDir 指定其他路径。

新建的虚拟环境、下载工具、安装缓存及任务临时文件均放在 D:\Codex 下。可以调用本机已有的 Python；不能据此向 C 盘安装新依赖或写入项目数据。安装前实际核对路径，避免上游自动缓存写入 C 盘。

已检查：D:\Codex 可以访问；原聊天工作目录只有空 Git 仓库；本机已有 Python 3.13，当前 PATH 未发现 FFmpeg。是否需要 FFmpeg 以及如何放置，以所选下载链路实测为准。

## 验收标准

1. 真实抖音公开视频：得到可播放原件、正确文案及发布时间；作品有公开定位时与页面标注一致，没有获取到时如实说明。
2. 真实抖音图集：图片数量、顺序和正文与原作品一致，所有文件保持正确格式。
3. 真实 B 站视频和图文：分别得到视频或正文加图片；发布时间正确；缺少公开定位时不编造。
4. 同一作品的短链接、长链接连续输入，只保留一份完整原件；已有不完整文件不能导致错误跳过。
5. 批次中含失效链接时，其他有效作品继续处理；失败有明确记录，最终退出码非零。
6. 登录失效或权限不足不能被报告为成功，不能将试看误当完整视频。
7. 用自动化测试验证中文与空格路径、Windows 非法文件名、时区转换、缺失字段、地点来源、重复链接、失败续跑和批次退出码。
8. 保存后核查实际文件路径及内容。自动化测试与真实平台验证分别报告；没有实际验证的类型明确列为未验证。

规格确认后，先进行平台工具的下载与字段可行性验证，再写实施计划和入口代码。若某个平台或定位字段无法稳定获得，先报告实测差距，不能悄悄更换需求或声称已支持。
